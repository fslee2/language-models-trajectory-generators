# What the legacy V4 Flash API name actually serves

On 2026-09-30, I sent the upstream `place the apple in the bowl` first-turn prompt to DeepSeek Chat Completions with `model="deepseek-v4-flash"`, `reasoning_effort="low"`, `temperature=0`, and an 8,000-token output cap. The request succeeded, but the response's `model` field was **`deepseek-flash`**. The [DeepSeek release notes](https://api-docs.deepseek.com/zh-cn/updates/) and [model list/pricing notes](https://api-docs.deepseek.com/quick_start/pricing/) explicitly say that V4 Flash has retired and the legacy name is routed to V4.1 Flash. This confirms API compatibility, not access to the original V4 weights. The model identifier in the response alone would not prove the backing weights; the provider documentation resolves that ambiguity.

This one alias response differs from the earlier `deepseek-flash` response even though the provider routes both names to the same current model. It first called `detect_object("apple")` and `detect_object("bowl")`, but then **invented sample coordinates** for both objects and emitted a full six-trajectory motion program before any real detection printout arrived. It used apple `[0.3, 0.4, 0.05]` and bowl `[0.5, 0.4, 0.05]` rather than the published detector results. This violates the upstream prompt's pause-after-detection rule and would be unsafe to treat as a valid trajectory. The generated Python was only parsed as text; it was never executed. No second API call or simulation was run for this attempt. The replay script now refuses a second-turn oracle replay whenever the first response includes motion or gripper calls.

The raw API response, usage, and AST call summary are in `ablations/results/place_apple_in_bowl_deepseek_v4_flash_low.json`. Its first-turn `finish_reason` was `stop`, and the request used the local key file without saving the key. A single stochastic response cannot estimate a success rate. The next useful comparison is physical evaluation of valid candidate plans in the original PyBullet scene, then GenieSim G2/RoboColyseum, with a strict gate that rejects invented coordinates or motion before detection.
